## Bot container does not start

- Check `docker compose logs -f bot` or `podman compose logs -f bot`.
- Confirm the generated root `.env` exists.
- Confirm required values are present, especially `DISCORD_TOKEN`, `SUPABASE_API_KEY`, `POSTGRES_PASSWORD`, and `DATABASE_URL`.
- Confirm `app/data/battlevive_tokens.json` contains a valid token pair, or both bootstrap token variables exist.
- Confirm the database service is healthy.

## Credentials are missing or invalid

The bot first reads the persisted token file. If it is absent or invalid, both bootstrap token variables are required.

Regenerate credentials through the supported setup flow:

```bash
cd utils
cp .env.example .env
./init.sh
```

## Battlevive requests repeatedly return 401

The client refreshes tokens after the first 401 and retries once. Repeated failures usually mean the refresh token is rejected or the persisted token file cannot be updated.

Regenerate credentials and confirm `/app/data` is writable and persistent.

## Database service is unhealthy

- Check `docker compose logs -f db`.
- Confirm `POSTGRES_PASSWORD` is set.
- Confirm bot traffic uses `db:5432`, not the host-only `127.0.0.1:5432` binding.

On SELinux hosts, PostgreSQL permission errors after recreating the bot can be caused by mismatched labels on overlapping mounts. Use shared `:z` labels on both mounts. Do not delete the database directory or recursively change its ownership for this error.

## Slash command fails

Inspect `app/logs/` or container logs. Typical causes are:

- missing Discord permissions;
- unavailable Battlevive or Supabase credentials;
- database connectivity failures.

For `/rank`, a channel-policy denial is private and does not start the cooldown. If the response asks you to wait, the accepted prior invocation consumed the configured cooldown even if later work failed. Administrators can inspect `/config show`, adjust channel rules, or temporarily set `/config rank cooldown seconds:0`.

An ambiguous identity means multiple active upstream users match the same Discord member name. Correct the upstream names so the match is unique, then retry; the bot intentionally links neither account automatically.

If notification-role configuration succeeds but deletion remains pending, restore Manage Roles and the correct role hierarchy, then rerun `/create_roles`, change the configured role again, or reset active-lobby configuration. Only the ownership-tracked generated role is retried.

If an account was restored with the same UUID, run `/refresh` or retry `/rank`; the retained recovery link is rehydrated automatically. A different UUID is treated as new and does not recover historical ratings or lobby data.

## Slash commands are missing or stale

Leave `DISCORD_COMMAND_GUILD_ID` blank for production global registration. Global updates can take time.

During development, set it to a positive guild snowflake and restart the bot for rapid guild-scoped registration.
