## Player commands

### `/rank`

Server-only public command that displays your Battlevive rank card from the globally current season, selected by the most recently updated rating data.

![BattleVive Bot response to the rank command](/images/rank-card.png)

On a local identity miss, the bot coalesces a users-and-ratings refresh and retries. `You are not registered.` is returned only after that authoritative refresh confirms absence. Registered users without a current-season rating receive a separate private response; upstream or database failures report that verification is unavailable. Server cooldown and channel rules are checked first.

## Server management commands

### `/refresh`

Requires **Manage Server** and can only be used inside a server.

The command:

- refreshes Battlevive users, lobbies, and season ratings;
- synchronizes the local database;
- updates MMR tier roles in the invoking server;
- requests leaderboard and active-lobby reconciliation.

Only one manual refresh can run at a time.

### `/create_roles`

Requires **Manage Roles** and can only be used inside a server.

Creates or validates all MMR tier roles plus the `Active Lobby` and `Website Moderator` notification defaults. Notification roles created by the bot are ownership-tracked; custom and legacy same-named roles are never adopted for automatic deletion.

The bot reports created, existing, rejected, and failed roles separately. Existing roles are accepted only when they are unprivileged, unmanaged, assignable, and below the bot's highest role.

### `/config show`

Requires **Manage Server**.

Displays the server's current leaderboard channel and limit, active-lobby channel, notification roles, moderator role, `/rank` cooldown, public-command whitelist and blacklist, and debug-export status. Long output is split across ephemeral follow-up messages.

### `/config rank cooldown seconds:<0..3600>`

Requires **Manage Server**. Sets the `/rank` cooldown per user and server. `0` disables it; the default is 20 seconds.

### `/config commands whitelist channel:<channel>`

Requires **Manage Server**. Adds or reclassifies a text or announcement channel as allowed. When any live allow rule exists, public commands are available only in allowed channels.

### `/config commands blacklist channel:<channel>`

Requires **Manage Server**. Adds or reclassifies a channel as blocked. A block rule always wins.

### `/config commands remove channel:<channel>`

Requires **Manage Server**. Removes the channel rule. Removing an unlisted channel is a successful no-op. Threads inherit their parent channel's rule, and deleted channels are ignored and cleaned from storage.

## Leaderboard configuration

### `/config leaderboard channel`

Sets the text or announcement channel used for leaderboard posts.

The bot must have:

- View Channel;
- Send Messages;
- Attach Files;
- Read Message History.

### `/config leaderboard limit`

Sets the number of leaderboard places from `1` through `50`. Omitting the amount uses `50`.

### `/config reset leaderboard`

Clears the leaderboard channel and limit and requests cleanup or reconciliation of managed leaderboard messages.

## Active-lobby configuration

### `/config active_lobbies channel`

Sets the text or announcement channel used for active-lobby posts.

The bot must have:

- View Channel;
- Send Messages;
- Embed Links;
- Attach Files;
- Read Message History;
- Mention @everyone, @here, and All Roles.

The final permission allows the bot to mention the configured notification role even when that role is not generally mentionable. Message-level allowed mentions still restrict each post to the exact configured role.

### `/config active_lobbies role`

Selects the role notified for newly observed lobbies. The role cannot be `@everyone` or integration-managed.

Omit the role argument to restore the generated `Active Lobby` role. Run `/create_roles` first if that role does not exist.

### `/config active_lobbies moderator_role`

Selects the role notified when a result first becomes disputed.

Omit the role argument to restore the generated `Website Moderator` role. Assign this role only to staff who can resolve results upstream.

### `/config reset active_lobbies`

Clears the active-lobby channel and notification-role settings and requests managed-post cleanup. Notification history is retained. Only ownership-tracked generated roles are deleted; failed deletions remain pending for later retries.

## Debug commands

### `/config debug enabled:<bool>`

Requires **Manage Server**. Debug exports are disabled by default and should be enabled only temporarily in a controlled server.

### `/debug_get_db_data`

### `/debug_get_battlevive_data`

Both commands require:

- Manage Server;
- server context;
- debug exports enabled for that server.

Each command returns three ephemeral, in-memory JSON attachments containing users, lobbies, and ratings. Exports do not write files to the persistent data directory. They may contain sensitive synchronized user and match data.
